# 第一版架构

## 设计选择

Electron 负责 Windows 原生窗口与离线静态页面加载；React 负责交互。主进程关闭 Node 集成、启用上下文隔离和进程沙盒，拒绝新窗口、页面导航与权限申请。生产 CSP 不允许远程脚本；仅开发服务器允许 React 刷新所需的内联脚本。

本版不存在特权 IPC，也不连接游戏进程。所有游戏输入由用户提供。

## 状态与持久化

`Session` 包含英雄 ID、实际已选、至多三个候选、等级、已有装备、敌方压力、偏好和可选的手动流派锁定。每次变更经过 `sanitizeSession` 校验。应用使用 localStorage 保存小型单局状态；尚无历史查询需求，因此暂不引入 SQLite 原生依赖。未来复盘再引入带迁移的数据库。

更换英雄清空本局状态并保留偏好；新一局保留英雄与偏好。损坏或未知字段被过滤，存储异常有可见提示。

## 推荐流程

1. 根据英雄种子路线的基础权重开始比较。
2. 已选海克斯按标签为路线提供匹配分；缺少触发条件的强化不参与该项加分。
3. 技能暴击路线在缺少关键机制时降权；盖伦自有机制另行处理。
4. 已有核心装备提供继续路线的倾向，减少无成本转型假设。
5. 偏好对承伤、成长和实验路线提供有限调整。
6. 候选逐个在复制的状态上模拟，绝不改变实际路线。
7. 手动锁定优先用于本局输出，但候选仍提示其他可能的方向。
8. 按实际等级生成 1–18 级合法加点，终极技能在 6/11/16 级提升。

规则分数是内部排序，不代表经过统计校准的收益或胜率。第一版未实现全装备冲突矩阵、经济模拟与实际技能点输入。

## 扩展接口

后续 `game-adapter` 或 `recognition` 应输出带来源、时间与置信度的建议状态，再让用户校正。不可直接将推荐候选写入已选。知识包未来采用 JSON Schema 与独立校验、签名；当前作为 TypeScript 内容模块在构建时打包，修改后需重新构建。
